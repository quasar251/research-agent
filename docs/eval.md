# 调研质量评估 Eval

> 本文定义研小报调研产出的质量评估方案。无直接对应的设计真源章节，参照业界 Deep Research Agent 评估方法论（DeepResearch Bench 的 RACE + FACT、SAFE、DREAM），并与研小报自身的状态结构对齐。

---

## 1. 评估目标与痛点

调研类 Agent 的评估核心难点是「**合成幻觉 Mirage of Synthesis**」：文字流畅、结构完整，但事实错误、引用失效、口径过时。评估必须穿透"看起来很好"，落到**可验证的事实与溯源**上。

评估三问：**报告写得全不全、结论靠不靠谱、过程能不能追溯。**

---

## 2. 三层评估维度

| 层 | 对应业界框架 | 回答的问题 |
| --- | --- | --- |
| 报告质量 | RACE（report quality） | 报告写得全不全、有没有洞察 |
| 事实与引用 | FACT（citation + factuality） | 结论靠不靠谱、引用真不真 |
| 过程质量 | 研小报特有（覆盖度 / 溯源） | 过程能不能追溯 |

---

## 3. 指标定义与评分规则

### 3.1 报告质量（对照报告结构 schema）

对照 `state.md` §1.4 的报告结构 schema，逐区块评估：

- **全面性**：deep 报告应覆盖 schema 中「全」标注的全部区块，simple 覆盖「简」标注区块，无缺章。
- **洞察力**：核心结论 KEY TAKEAWAYS 是否有增量判断，而非罗列数据。
- **指令遵循**：是否遵循用户澄清的口径、深度、关注维度（对齐 `memory.md` 的用户偏好）。
- **信息密度**：关键指标（市场规模、CAGR）是否落在头部执行摘要，一眼可见。

### 3.2 事实与引用（FACT 式）

- **引用精度 / 召回（citation precision / recall）**：结论引用的来源是否正确对应、是否覆盖了支撑结论的关键来源。
- **引用三要素**（对齐 Cited-but-Not-Verified 框架）：
  - 链接可达性：引用 URL 有效、可访问
  - 内容相关性：引用内容确实支撑该结论
  - 事实准确性：结论与来源事实一致，无"有引用但未验证"的情况
- **claim 级事实核查**（SAFE 式）：把结论拆成原子 claim，逐条判定 supported / unsupported / contradicted。

### 3.3 过程质量（研小报特有）

与状态结构直接映射：

| 指标 | 映射 | 说明 |
| --- | --- | --- |
| 覆盖度 | 研究矩阵（`state.md` §2.2） | 0~1，格子状态派生；越低说明缺口越多 |
| 证据强度分布 | 结论 Claim 的证据强度 | 四档（实锤/推断/共识/分歧）的占比，实锤占比越高越可信 |
| 溯源完整性 | 证据台账 → 结论 → 报告的引用链 | 每条关键结论能追溯到来源、角色、时间 |
| 无静默缺口 | 研究矩阵格子状态 | 不存在未处理且未标 unresolved 的 gap |

---

## 4. 评估方法

1. **rubric 评分**：报告质量按 RACE 式加权打分表，逐项给分。
2. **claim 级事实核查**：结论拆原子 claim，检索判定支持 / 不支持 / 矛盾。
3. **引用三要素核验**：对每条引用做可达性、相关性、准确性检查。
4. **过程指标自动计算**：覆盖度、证据强度分布、溯源完整性从状态直接派生，可机器计算，无需人工。

---

## 5. 与状态结构的映射汇总

| 评估维度 | 依赖的状态实体 |
| --- | --- |
| 报告质量 | 报告结构 schema（`state.md` §1.4） |
| 事实与引用 | 证据台账 + 结论 Claim 的证据引用 |
| 覆盖度 | 研究矩阵 |
| 证据强度分布 | 结论 Claim 的证据强度字段 |
| 溯源完整性 | 证据台账 / 结论 / 检查点 / 上下文快照 |

---

## 6. 生产级关注点

### 6.1 评估数据集

- 预置带标注的评估集：题目 + 黄金结论 + 引用标注。
- 分层：simple / deep、不同行业域，覆盖覆盖面。

### 6.2 基准

- 记录各模型 / 配置在评估集上的基线分数。
- 任何模型或 prompt 变更前，先跑基准对比。

### 6.3 回归门禁

- 评估分数低于基线阈值（如相对下降 > 5%）则阻止上线（见 `operations.md` §6）。
