## 2. 三条边界

**边界一 · 输入侧（注入防护）**

- 所有外部内容（网页、PDF、用户上传）进入模型前，过注入扫描。
- 关键约束：**检索到的内容一律标记为不可信数据**，不进入 system instruction 层级，只作为分析素材进上下文（防网页嵌入指令被搜集 Agent 当作"研究指令"执行）。

**边界二 · 用户隐私保护**

- 用户上传的私有文件 / 敏感输入（如个人身份信息）在写入审计日志前做脱敏（mask / hash / remove 三模式）。
- ToC 场景隐私压力低于 B 端，仅需约束"用户私有数据"边界，无需 B 端的客户名称 / 财务数字三级治理。

**边界三 · 可审计溯源**

- 每条关键结论可追溯到：哪个 Agent、什么上下文、基于哪个来源、以什么证据强度。
- 上下文快照、状态检查点、来源台账在**同一审计语义**下对齐。

---

## 3. 安全的组织方式

- **隐私处理模式**：mask / hash / remove 三档（仅用户私有数据）。
- **审计事件**：事件类型（上下文编译 / 状态写入 / 工具调用 / Skill 加载 / 派发 / 注入扫描 / 隐私脱敏）、主体、已脱敏载荷、溯源链、时间。
- **权限要求**：所需 Tool 列表、作用范围。

---

## 4. PermissionGate 归属

- 权限判定（PermissionGate）归属安全模块，横切所有 Tool 调用（Tool 定义见 `tool.md`）。
- 工具侧只保留 Tool Registry，不做权限判定（Registry 与权限分离）。

---

## 5. 关键设计点

- 证据强度四档（实锤 / 推断 / 共识 / 分歧）、来源等级三级（1 / 2 / 3）治理，可直接编码为 Skill 与调度规则（证据强度低于阈值时自动降级标注），而非依赖人工事后审查。

> 裁剪说明：原设计的"独立核查方否决权"是风控 / 合规的治理语义，调研里证据弱就标弱或 unresolved 即可，已移除。
