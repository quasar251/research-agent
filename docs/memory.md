# 记忆 Memory

> 本文对应《扩展设计》`agent-extended.md` 的 §2 记忆模块，并承接第二档功能 ⑥ 的记忆侧。
> Memory 是状态的**跨会话投影**：跨任务沉淀的知识，与本次任务状态严格解耦。

---

## 1. 职责

记忆是状态的**跨会话投影**，与状态严格解耦。ToC 个人场景两层即可：

| 层 | 内容 | 存取方式 |
| --- | --- | --- |
| 核心记忆 | 常驻上下文、可编辑的记忆块 | 常驻注入 |
| 长期记忆 | 个人跨任务沉淀的结论 / 口径 / 来源 / 关注维度，用命名空间细分 | 检索式（向量 / 结构化库） |

> 裁剪说明：不设企业知识库 / 领域知识库，不设 enterprise 级跨用户共享——ToC 单用户没有"企业上传分类框架 / 统一口径"的协作需求，个人知识即长期记忆的全部内容。

---

## 2. 记忆的组织方式

- **scope 显式设计**：每条记忆带 scope，取值 run（本次任务）/ user（个人跨任务）。ToC 单用户两档够用。
- **核心记忆块**：常驻内容 + scope + 是否可编辑 + 更新时间。
- **长期记忆条目**：检索式存储，含命名空间（结论 / 口径 / 来源 / 关注维度 / 用户偏好）、内容、来源引用、冲突标记。
- **用户偏好**：scope=user 的长期记忆，由对话中写时提取，含偏好维度、置信度 / 出现频次、来源引用（哪次对话提取）、是否可编辑。

---

## 3. 与其他模块的耦合

- **从状态蒸馏**：任务收尾时，由**蒸馏节点**（pipeline 的收尾步骤，非独立常驻进程）把验证有效的结论 / 框架 / 来源 / 口径沉淀为长期记忆。

> 裁剪说明：原设计的 "sleep-time Agent 空闲期巩固" 是持续对话型 Agent 的机制，调研是任务驱动型、无空闲期，已改为任务收尾的普通节点。

- **写时处理优先于检索**（2025–2026 共识）：写入时用 LLM 做结构化提取、冲突检测与整合，而非存原始数据检索时再处理。
- **冲突标记而非静默覆盖**：抓到的来源与已有记忆矛盾时，标记冲突，不覆盖。

---

## 4. 跨会话复用（⑥ 持续监测的记忆侧）

第二档功能 ⑥，记忆侧负责长期记忆的跨会话复用：

- 已沉淀的长期记忆（结论 / 口径 / 来源）在新任务 align 阶段被检索复用。
- 调度侧据此触发短简报（见 `orchestration.md` §6）。

---

## 5. 关键设计点

- 个人长期记忆（user）与本次任务记忆（run）不混用。
- 写入长期记忆的是**结构化结论 / 事实**（实体 / 指标 / 时间 / 来源可信度），不是抓取全文。

---

## 6. 生产级关注点

### 6.1 检索实现

- 长期记忆采用检索式存储：结构化库（SQLite）+ 可选向量检索。
- 检索先按命名空间（结论 / 口径 / 来源 / 关注维度）过滤，再按相似度排序。

### 6.2 索引

- 长期记忆表索引：`(namespace, scope)`。
- 若引入向量检索，单独建向量索引，与结构化字段解耦。

### 6.3 淘汰策略

- 冲突标记而非覆盖（写时处理，见 §3）。
- 淘汰：低频 + 过期记忆归档，高频记忆保留；淘汰不影响已有关联结论的溯源。
