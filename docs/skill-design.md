# Skill 设计

> 本文对应《扩展设计》`agent-extended.md` 的 §3 Skill 模块。
> Skill 是上下文的**受控注入**，教 Agent 如何组合已获准的能力；核心机制是**渐进式披露**。

---

## 1. 职责

**MCP 给 Agent 新能力，Skill 教 Agent 怎样组合已获准的能力**。两者必须分开，Skill 不构成隐式权限升级。

| 类型 | 内容 | 举例（行业调研） |
| --- | --- | --- |
| Tool / MCP | 原子能力 | 网页抓取、搜索引擎、PDF 解析、数据库查询、图表生成 |
| Skill | 组合知识 | SWOT 分析流程、竞品定价口径、财务可视化规范、报告章节结构 |

---

## 2. Skill 定义与组织

- **Skill 定义**：唯一 id、名称、绑定阶段、正文（Markdown 或结构化定义）、引用的 Tool 列表（仍需过 PermissionGate）。
- **路由结果**：每个新子任务开始时返回本轮活跃 Skill 集合。

> 裁剪说明：原设计的"活跃 / 非活跃集合 + 冲突裁决规则"是通用 skill 编排器的防御设计。调研 Skill 数量有限，按阶段路由已天然互斥，已移除冲突裁决。

---

## 3. 渐进式披露机制

Skill 注入的是**长文本流程知识**，直接吃上下文窗口，因此必须渐进式披露，不能一次性塞满：

1. **随阶段路由**：Skill 绑定阶段，搜集阶段的 Skill（多角度查询生成）与分析阶段的 Skill（交叉验证）**不应同时**出现在一个 Agent 上下文。
2. **按需加载**：通过 prepare_context 按需加载，不一次性塞满。
3. **子任务级返回**：每个新子任务开始时，先调路由入口，返回本轮活跃 Skill 集合。

---

## 4. 与其他模块的耦合

- **受控注入上下文**：Skill 是上下文的一种注入形式（见 `context.md`）。
- **绑定权限边界**：Skill 正文不构成新执行权限；引用的 Tool 仍走 PermissionGate（见 `security.md`）。
- **间接约束工具使用**：Skill 通过「引用的 Tool 列表」间接约束某个阶段实际会用到哪些 Tool，而不是直接裁剪 Tool schema（见 `tool.md`）。

---

## 5. 关键设计点

- 每个新子任务开始时，先调路由入口，返回本轮活跃 Skill 集合。
- 最小权限：某调研项目不需要的 Tool，不进入该项目的 Tool Registry。

---

## 6. 生产级关注点

### 6.1 版本管理

- Skill 带版本号，正文每次变更即升版。
- 子任务引用 Skill 时记录版本，保证可复现（"当时用的哪个版本"）。

### 6.2 升级兼容

- 升级不改变已运行任务的活跃 Skill 集合（快照锁定）。
- 旧版本保留到无引用后再下线，避免历史任务回溯失败。
